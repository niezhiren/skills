# 开发 ClassIn 网页课件

让教师通过一个 HTTPS 链接在教室内打开课件，并用鼠标或一根手指完成整堂课的核心操作。已有项目先检查生产构建、输入处理和实际打开方式，保留现有技术栈；简单的新课件优先用 HTML、CSS、JavaScript 或项目已有的轻量框架。

## 1. 确定打开入口和最低内核

从项目资料、客户设备清单或目标客户端实际打开的页面中确认：产品（ClassIn 或 ClassIn X）、系统与架构、客户端版本、打开入口、谁负责操作。普通教室浏览器、URL 课件（如 EDU）和多向浏览器是不同入口；在最终交付的入口测试。普通 URL 页面以标准 Web 能力运行，不把 ClassIn 私有 JS Bridge、课堂身份或教室同步当作默认能力。要接入 EDA 或其他专用工具时，先取得对应的正式接入文档。

下表是 **2026-11-05 核对的客户端构建配置**。版本号指嵌入的 Chromium；它既不是客户端版本，也不是安装在系统里的 Chrome/Edge 版本。不同发行渠道、旧包和定制设备可能不同，最终用目标入口内页面的 `navigator.userAgent` 中的 `Chrome/` 版本交叉核对。

| 目标 | 已核实的 Chromium 构建配置 | 开发时如何选 |
| --- | --- | --- |
| Windows ClassIn / ClassIn X | Qt 5 构建为 **109.0.5414.120**（含 Win7 SP1 兼容构建）；Qt 6 x64 构建为 **138.0.7204.310** | 版本未知时按 109；Win10/11 也不能仅凭系统版本认定为 138 |
| macOS ClassIn（Intel / Apple 芯片，按实际安装包） | Qt 5 构建为 **109.0.5414.120**；现行 Qt 6 构建选择 **138.0.7204.310** | 按设备清单中的最老包验收；大屏 ClassIn X 的公开发行版是 [Windows 版](https://www.classin.com/download/) |
| Linux ClassIn（x64 / ARM64，含相关国产发行版） | 现行构建为 **138.0.7204.310**；已核实的旧构建为 **103.0.5060.134** | 覆盖存量或包未知时按 103；测试实际发行版与架构 |
| 鸿蒙 PC ClassIn（采用 CEF 的客户端） | **114.0.5735.248** | 在鸿蒙 PC 客户端内验收，不用此表推断 Android、iOS 或其他 WebView |

**没有设备清单时，兼顾 ClassIn 和 ClassIn X 的默认开发目标是 Chromium 103。** 如果明确只覆盖上述 Windows/macOS 构建，可以用 109。103 和 109 是保守的工程基线；遇到更旧的实测内核，按实际最低版本另行处理。只有所有目标安装包已核实，才提高构建目标。不要按 UA 分叉主流程；用 UA 记录环境，用功能检测和实际运行结果决定增强能力。

## 2. 确保生产产物在最低内核可运行

- 显式配置生产 JS 的目标，例如 esbuild 使用 `target: 'chrome103'`；工具单独配置 CSS 目标时一并设置。检查入口、异步 chunk、Worker 和直接加载的第三方脚本；它们都可能让老内核启动失败。[esbuild target 文档](https://esbuild.github.io/api/#target)
- JS 转译不会补齐运行时 API。基础流程使用已验证的 Web API，逐项检查依赖；例如 `Array.prototype.toSorted` 可用 `items.slice().sort(compare)` 实现相同的浅拷贝排序意图。需要 WebGPU、WebCodecs、剪贴板、全屏或设备权限时，检查能力、处理调用失败，并保留能上课的替代流程。即使内核足够新，嵌入容器也可能限制能力。GPU 增强效果应有 DOM、SVG、Canvas 2D 或静态图等替代。[Chrome WebGPU 能力说明](https://developer.chrome.com/docs/web-platform/webgpu/troubleshooting-tips)
- 首屏和核心控件用 Flexbox/Grid、媒体查询与常规选择器实现；103 下别让尺寸容器查询或 `:has()` 承担核心布局（Chromium 105 起支持）。用普通类和事件实现基础状态，再按需用 `@supports` 增强。原生 CSS 嵌套应在构建时展开，或用普通规则替代。[Chromium 105 的 CSS 说明](https://developer.chrome.com/blog/new-in-chrome-105) · [CSS 嵌套说明](https://developer.chrome.com/docs/css-ui/css-nesting)
- 在生产 HTTPS 地址上验证首屏和所有动态资源。尽量同源托管脚本、样式、字体和媒体；跨域 API 要正确配置 CORS。避免混合内容、`file://`、本机地址、必须跳出客户端的登录、新窗口或下载流程。优先在同一页完成教学；刷新和深链接能直接打开。若使用第三方 iframe，单独验证嵌入策略、登录和课堂网络可达性，并准备同页或可直接打开的替代内容。
- 声音从可见的“播放”按钮启动，在该次用户操作中调用 `play()` 或恢复 AudioContext，并处理拒绝及加载失败。视频可准备 MP4（H.264/AAC）与 WebM 等备选；用 `canPlayType()` 初筛、用目标客户端实际播放和拖动进度验证，不能凭 Chrome 主版本承诺解码。关键内容配字幕、图文或静态备份。需要学生听到声音时，分别验收本地播放和学生端的课堂共享声音。[Chrome 自动播放策略](https://developer.chrome.com/blog/autoplay)

### 网页 TTS 朗读与口音选择

**ClassIn PC 和 ClassIn X 的内置浏览器不支持 Web Speech API 的在线 TTS 音色**，例如桌面 Chrome 提供的 Google US English。通过 `speechSynthesis` 朗读时，使用目标设备已安装、由内置浏览器实际枚举出的本地语音。预生成的语音文件可以按普通网页音频播放。

- **先选口音，再选本地音色。** 用 `speechSynthesis.getVoices()` 枚举，只保留 `localService === true` 且 `lang` 与目标地区精确匹配的声音。比较前统一大小写和连字符，例如美式 `en-US`、英式 `en-GB`、澳式 `en-AU`。优先使用本机试听通过的声音，例如 macOS 的 Samantha（美式）、Daniel（英式）、Karen（澳式），以目标设备的实际列表为准。需要记住用户选择时，用 `voiceURI` 在当前候选列表重新匹配。
- **点按播放时明确传入音色。** 把选中的声音赋给 `utterance.voice`，同时将 `utterance.lang` 设为目标地区。只设置 `lang` 会让浏览器自行选音。首读列表为空时监听 `voiceschanged` 并重新枚举。API 缺失、没有对应地区的本地声音、合成报错或等待播放超时时，提示原因并提供已录制或预生成的同口音音频。避免静默换成另一个口音。
- **需要统一示范发音时，直接播放同一份音频。** 同一口音可以有多种音色，系统音色会随设备和语音包变化。验收时在目标客户端入口试听同一句、同语速，核对传入的音色、地区和本地来源，并检查音色缺失时能否继续播放。 [Web Speech API 选音与本地语音说明](https://webaudio.github.io/web-speech-api/#speechsynthesisvoice-attributes)

## 3. 让 ClassIn X 大屏用一根手指就能上课

### 宿主会参与手势分配

- **浏览/交互模式**：普通网页浏览入口会把网页区域内符合条件的触摸交给内置浏览器。在此模式实现和验收单指点击、滚动与拖动。部分入口或设备会把触摸合成为鼠标/点击事件，事件类型和顺序不应写死。
- **批注/书写模式**：在普通教室浏览器共享窗口中，覆盖网页的白板可接管单指或笔输入。部分构建会识别双指滚动或缩放，并由宿主处理或转发。网页的 `preventDefault()`、`touch-action` 和 pointer capture 只能影响已经进入网页的输入。教学提示可写“如果点按变成书写，请退出批注，切回浏览/交互模式”。
- **多点和笔不是必需能力**：触控锁、笔模式、硬件、驱动和入口都可能改变事件路由。不要把白板的多人同写、橡皮擦、压感或掌拒当作网页能力；部分 CEF 输入路径不会保留真实压力、接触面积或旋转角。不要把双指捏合、双击、长按、右键或精确识别 `pointerType` 作为通关条件。

### 网页交互规则

- 使用原生 `button`、`input` 等控件。按钮用一次 `click` 完成操作，兼顾鼠标、触摸和键盘；不要在 `touchend`、`pointerup` 和 `click` 中重复提交。把 hover 才显示的功能改成可见按钮或点按菜单。建议主要触控目标至少 **48 × 48 CSS px**，按钮间留出间隔，避免贴着宿主标题栏和工具栏；以实际容器内显示大小和老师操作距离为准。
- 拖动或绘画用 Pointer Events：在 `pointerdown` 记录 `pointerId`，按需捕获指针，移动时只更新匹配指针；`pointerup` 提交，`pointercancel`、异常失去 capture、页面隐藏或组件卸载时清理拖动状态，且不误提交。接受鼠标路径；`maxTouchPoints` 仅用于诊断，不能据此判断当前事件来自手指。不要把 HTML `draggable`、系统拖放或长按启动作为唯一交互；宿主原生拖放支持随入口和版本变化。
- 默认保留页面原生滚动；自定义拖动区域才设置 `touch-action`，例如横向拖动区用 `pan-y` 保留竖向滚动，独立绘画区按需用 `none`。不在整个页面禁用滚动或缩放。对拖拽题提供“点选物件 → 点选目标”，对缩放、翻页提供可见的 “＋ / − / 上一页 / 下一页”，同一逻辑处理两条操作路径。[W3C Pointer Events](https://www.w3.org/TR/pointerevents3/)
- 按网页容器的 CSS 像素布局，兼容非全屏、小窗、横向大屏和 Windows 显示缩放。不要按 1920×1080 或 4K 物理分辨率固定定位。Canvas 命中用 `clientX/Y` 减去 `getBoundingClientRect()` 的边界，再按实际绘图坐标系与 CSS 尺寸的比值转换；绘图缓冲区与布局尺寸分开管理。缩放或调整窗口后重新取边界，避免画面在一处、触点在另一处。

## 4. 让低配设备和课堂共享都流畅

- 用最慢的目标设备和学校网络定预算。首屏优先显示题目和可点控件，后续页图片和媒体按需加载；用课件实际展示尺寸导出素材，视频优先从 720p 或 1080p 试起，避免默认加载 4K 视频和整套课件。加载失败提供重试及可继续讲课的图文内容。
- 连续拖动只在 `requestAnimationFrame` 合并刷新视觉状态；计分、提交和同步在确认时执行。减少反复布局、全屏模糊、重型 SVG 滤镜、全屏高分辨率 Canvas 和常驻动画。大屏卡顿时先降低 Canvas 渲染分辨率、粒子数或特效，再降低交互功能。页面隐藏时暂停非必要的动画和媒体，退出时释放定时器、事件监听器与大资源。
- 明确是“老师演示，学生观看”还是“学生可在各自设备操作”。普通 URL 页面不要假设师生共享同一份 JS 状态、Cookie 或本地存储。若业务需要多端共答，用受控服务端状态或经正式接入的同步接口。用实际的课堂共享方式验证学生端画面、字体、Canvas、音视频和重新进入；只在老师本机打开成功不能证明共享成功。

## 5. 验收和交付

用**生产构建**和同一 HTTPS 地址验收。桌面 Chrome 或自动化测试可提前发现 JS、CSS 和网络问题；触摸模拟无法证明 ClassIn X 的输入路由、批注、软键盘和实际帧率。

| 检查 | 通过条件 |
| --- | --- |
| 最低内核、每个承诺的平台和实际打开入口 | 首次打开、刷新和二次打开成功；无阻断性 JS、资源、证书或 CORS 错误；进入题目、操作、提交、反馈、重来均可完成 |
| Windows ClassIn X 真机 | 浏览模式下单指点按一次只触发一次，能滚动、拖动或通过点选完成等价操作；拖出区域、误触第二指、切换批注再回来，交互不会卡死或误计分 |
| 缩放与布局 | 小窗和大屏全屏可见且可点；在学校实际使用的显示缩放下，控件、滚动区、画布坐标和文字正常；需要打字时验证软键盘和中文输入 |
| 媒体与共享（按课件使用情况） | 从点按启动，暂停、续播和进度正常；老师端与学生端均按教学预期显示/出声；媒体失败可继续讲课 |
| 性能与恢复 | 在最慢目标设备上记录冷启动到首次可操作的时间；连续操作和翻页、断网恢复、关闭重开无明显卡顿、失控或持续内存增长 |

排障时先记录客户端版本、系统和架构、大屏型号、入口、浏览/批注模式及复现步骤。再从**客户端内打开的页面**记录 `navigator.userAgent`、`navigator.maxTouchPoints`、`innerWidth`、`innerHeight` 和 `devicePixelRatio`。触摸异常时可临时显示最近几条 `pointerdown/move/up/cancel`、`lostpointercapture` 和 `click` 的类型、指针 ID 与坐标；不要把诊断或课堂个人数据留在正式页面里。若点击根本没进入网页，先检查宿主模式、触控锁和入口，再改 Web 事件代码。

交付给客户：**可打开的 HTTPS 地址、构建目标与使用说明、已通过的设备/客户端/入口、尚未验证的组合，以及双指、触控笔和媒体失败时的替代操作**。没有真机的组合标记为“待真机验收”，可先交付网页和精简复测步骤。
